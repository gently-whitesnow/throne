# Как контрибьютить в Throne

Спасибо за интерес к проекту. Throne — **локальное приложение агентной инженерии
вокруг намерения (Intent)**. Полный разворот миссии — [readme.md#Миссия](readme.md#миссия);
держи его как ориентир: каждый PR должен работать на миссию, а не размывать её.

Участие в проекте регулируется [Кодексом поведения](CODE_OF_CONDUCT.md).

## Процесс

1. Форкни репозиторий и заведи ветку от актуального `master`
   (`type/short-slug`, напр. `feat/intent-links` или `fix/glab-stdin`).
2. Внеси изменение. Держи PR узким и сфокусированным на одном осмысленном проходе.
3. Прогони quality gates локально — они запускаются перед каждым коммитом и в CI:

   ```bash
   bash scripts/quality/verify.sh              # backend + frontend
   bash scripts/quality/verify.sh --scope backend
   bash scripts/quality/verify.sh --scope frontend
   ```

   Падает — чини root cause, не отключай гейт. Ослабление гейта требует rationale
   в коммите (см. [ROOT.md](ROOT.md)).
4. Открой PR в `master` с описанием по шаблону ниже.

## Описание PR

Описание PR — не формальность, а вход для ревьюера. Сгенерировать заготовку по
diff/коммитам помогает skill [`skills/pr-description`](skills/pr-description/SKILL.md)
(`skills/pr-description/bin/throne-pr-description scaffold`).

**Обязательные разделы:**

- **Что** — что меняется. Список существенных изменений, а не пересказ diff построчно.
- **Зачем** — какую задачу или проблему решает PR.
- **Привязка к миссии** — как изменение служит миссии (локальное приложение агентной
  инженерии вокруг Intent) или почему оно к ней нейтрально. Если не получается связать —
  это сигнал, что изменение стоит пересмотреть.

**Рекомендуемые разделы:**

- **Решения** — ключевые выборы и почему именно так.
- **Отброшено** — какие альтернативы рассмотрены и почему отклонены.
- **Ограничения** — что осталось за рамками прохода или известные ограничения.
- **Проверка** — как проверить: какие гейты прогнаны, что проверено вручную.

## Коммиты

Один коммит на осмысленный проход. Формат заголовка — `тип(модуль): описание`:

```
feat(intent): связи между intent'ами
fix(api): utf-8 bom в stdin glab
docs(mission): единая формулировка миссии по витринам
```

Типы: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `build`, `ci`.
В теле коммита при необходимости — блоки «Решения» / «Отброшено» / «Ограничения»
(пустой блок опускай).

## Лимит бизнес-логики: ≤600 строк на PR

Один PR несёт **не больше 600 строк бизнес-логики** (сумма добавленных и удалённых
строк diff). Крупнее — декомпозируй на несколько PR. Лимит держит проходы обозримыми
для ревьюера и защищает миссию от «размывающих» мега-PR.

**Бизнес-логика** = строки diff **минус** файлы из списка исключений ниже. Исключения
не считаются в бюджет, потому что это не ручная логика, а сопутствующий или машинный код:

- **Тесты** — `**/*Tests/**`, `**/tests/**`, `**/__tests__/**`, `*.test.*`, `*.spec.*`,
  `*_test.go`.
- **Сгенерированное** — `*.g.*`, `*.generated.*`, `**/migrations/**`, `**/__snapshots__/**`,
  `*.snap`, `*.received.*`, `*.verified.*`, `apps/api/nswag/**`, `*.generated.css`.
- **Lockfiles** — `pnpm-lock.yaml`, `package-lock.json`, `yarn.lock`, `go.sum`, `*.lock`.
- **Документация** — `*.md`, `*.mdx`, `specs/ADR/**`.
- **Ассеты** — `*.png`, `*.jpg`, `*.jpeg`, `*.gif`, `*.webp`, `*.svg`, `*.ico`,
  `*.woff`, `*.woff2`, `**/public/**`.

Посчитать бюджет по своему diff:

```bash
skills/pr-description/bin/throne-pr-description loc --base origin/master
```

Автоматической проверки лимита в CI пока нет — правило соблюдают **автор и ревьюер**.
Список исключений выше — источник правды; если он расходится со скриптом, правь оба.
