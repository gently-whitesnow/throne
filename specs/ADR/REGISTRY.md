# ADR Registry

## Foundational (affect all code)
<!-- Cross-cutting decisions: architecture style, storage, deployment model -->

> **Нумерация ADR.** Номера immutable и не переиспользуются. Пропуски в нумерации — это либо решения, свёрнутые в их преемников (тело ADR удалено, нужный контекст инлайнен в активный ADR), либо номера, которых никогда не было (`0010`, `0012`). Висячие ссылки на несуществующий `ADR-0012` (легаси multi-user owner-scoping) резолвятся в [ADR-0029](0029-local-first-invariant-and-legacy-auth.md): этот слой демонтирован, ядро Throne — single-operator local-first, owner-оси нет.

- [ADR-0029](0029-local-first-invariant-and-legacy-auth.md) — Local-first инвариант: ядро Throne — однопользовательский local-first кокпит ([ADR-0027](0027-runtime-model-native-host-process.md) host-режим) без сетевого auth-гейта. Внутренняя авторизация — **вне** продуктовой поверхности. **Update (2026-06-06):** легаси-слой демонтирован — `owner_user_id`/`ICurrentUserAccessor`, внутренняя авторизация (PAT/JWT/OAuth — предложение поднять OAuth 2.1 на MCP-эндпоинте отклонено здесь же) и per-user `user_id`-дискриминатор удалены из кода и persistence; гард `OwnerUserIdRulesTests` снят. Фантомная ссылка `ADR-0012` резолвится сюда. Новые сущности (repository binding, project/task-memory) не проектируются вокруг owner-оси — её нет. Roadmap-правило: командные воркспейсы, если появятся, — отдельный сервис со своей governance, через собственный ADR, а не растягивание локальной модели. Закрытый ранее Out of scope (удаление `owner_user_id`, внешняя авторизация) — выполнен; построение команд остаётся out of scope.
- [ADR-0001](0001-foundation-clean-architecture-monorepo.md) — Foundation: Clean Architecture в монорепо `apps/api` + (будущий) `apps/web`. .NET 10, MongoDB, official MCP SDK, CPM, xUnit + Testcontainers.
- [ADR-0002](0002-domain-model-and-text-versioning.md) — Domain model `Intent`/`Instruction`: компактный canonical-документ (`text` + `current_version` + `tags`), единая коллекция `text_versions` в delta-формате (v1 snapshot, v2+ replace/insert), отдельные коллекции `intent_qa` / `intent_review` (training-only, агенту невидимые) — последние удалены в [ADR-0017](0017-removal-of-review-stage.md), optimistic concurrency через `expected_version` + typed `ApiException`.
- [ADR-0003](0003-mcp-text-editing-semantics.md) — MCP text-editing semantics: 9 tools для MVP (4 read + 5 write Intent). Отдельный `add_intent_qa` (decoupled от edit) — удалён в [ADR-0017](0017-removal-of-review-stage.md), actionable error codes (`match_not_found` / `match_ambiguous` / `version_conflict` / `line_out_of_range`), серверный `get_instruction_bundle(mode, intent_id?)` как единственный путь работы агента с инструкциями. Инструкции редактируются пользователем напрямую (mongosh / будущий HTTP), агентского write-surface для них нет. Запрет `full_replace` / `replace_by_line_range` / `list_*` / `include_text?`.
- [ADR-0004](0004-mcp-call-audit-log.md) — MCP call audit log: append-only коллекция `mcp_call_log` (tool_name, arguments, intent_id, session_id, outcome, error_code, duration), middleware на границе `Throne.Api`, best-effort запись через порт `IMcpCallLogSink`. Гарантия покрытия by construction (единая registration-helper + architecture test + startup fail-fast + параметризованный smoke-тест). База для dogfooding-телеметрии и будущего обучения системы.
- [ADR-0005](0005-frontend-foundation-fsd-quality-harness.md) — Frontend foundation: `apps/web` на Vite + TypeScript + React, FSD 2.0 layout (`app/pages/widgets/features/entities/shared`) и отдельный frontend quality harness с обязательным Steiger gate. Общий `verify.sh` запускает backend + frontend, `--scope` позволяет гонять только нужную часть.
- [ADR-0006](0006-openapi-contract-first-codegen.md) — OpenAPI contract-first: `specs/contracts/<module>/openapi.yaml` — единый источник правды для HTTP API. Backend DTO + abstract AspNetCore controller генерируются NSwag, frontend `types.ts`/`endpoints.ts` — `openapi-typescript`. Quality gate `contracts` ловит drift. Правила расширения — в `specs/contracts/AGENTS.md`.
- [ADR-0008](0008-realtime-contract-first-events.md) — Realtime contract-first events via domain events: `specs/contracts/realtime/events.yaml` — единый источник правды для server-to-client realtime. Транспорт SSE (`GET /api/v1/realtime/stream`), in-memory broker. Repository outcomes реализуют `IDomainEventCarrier`; декоратор `DomainEventDispatchingUnitOfWork` автоматически фанаутит события через `IDomainEventDispatcher`; `RealtimeDomainEventHandler` маппит их в SSE. Pipeline pluggable: новые handlers (внешний брокер, история, read-models) подключаются регистрацией в DI без изменения handlers/Application. Frontend — типобезопасный `useRealtimeEvent`. Quality gate `realtime` падает, если событие добавлено только в yaml, или только на бэке, или только на фронте.

## Module-scoped (affect one bounded context)
<!-- Decisions scoped to specific modules -->

- [ADR-0009](0009-cross-process-realtime-fanout.md) — Cross-process realtime fanout: все MCP-write должны входить в `Throne.Api /mcp`, чтобы мутации, domain events и SSE-фанаут жили в одном процессе. Изначально это обеспечивал отдельный stdio→HTTP proxy; после [ADR-0037](0037-direct-http-mcp-for-standalone-agents.md) standalone-клиенты подключаются к `Throne.Api /mcp` напрямую, а proxy удалён.

- [ADR-0037](0037-direct-http-mcp-for-standalone-agents.md) — Direct HTTP MCP for standalone agents: standalone-подключение переезжает на прямой Streamable HTTP `http://localhost:5008/mcp` для Claude Code, Cursor и Codex; embedded-терминал остаётся приоритетным контуром (ADR-0034). Mini-router из ADR-0014 сохраняется и отдаётся `Throne.Api` напрямую; realtime-фанаут из ADR-0009 не ломается, потому что все MCP-write всё ещё входят в процесс `Throne.Api` с in-memory SSE broker. Claude Desktop поддерживается через стандартный внешний bridge `npx mcp-remote http://localhost:5008/mcp --allow-http`, без собственного proxy в репозитории.

- [ADR-0014](0014-mcp-initialize-instructions-routing.md) — Доставка runtime-инструкций через MCP `InitializeResult.instructions`: на каждом MCP-handshake Throne сервер отдаёт короткий mini-router (`ThroneServerInstructions.MiniRouter`). Он формулирует условный глоссарий: явная просьба прочитать бандл → `get_prompt_bundle(mode, intent_id?)`; задача без имени бандла → выбрать режим по смыслу (`work` / `interview` / `dream` / `schema_map`) и прочитать бандл. Слеш-команды `/tinterview | /twork | /tdream` упразднены; вход в standalone-поток — естественный язык или copy-кнопка с явной просьбой прочитать бандл. Stdio-прокси пробрасывает upstream `ServerInstructions`. UI-страница `/instructions` рендерит bundles-tree вместо skills-tree. Часть про сбор review через `add_intent_review` superseded by [ADR-0017](0017-removal-of-review-stage.md). Строка mini-router'а для режима `dream` позже переписана под frontier-driven flow ([ADR-0022](0022-frontier-driven-dream-flow.md)); имя режима `dream` сохраняется.

- [ADR-0013](0013-mcp-attachment-delivery-tools.md) — MCP attachment delivery via per-type tools: `get_intent.attachments[]` отдаёт `kind`/`recommended_tool`/`compressed_dimensions`; pull через `read_intent_attachment_image` (нативный vision-блок) и `read_intent_attachment_text` (UTF-8-aware byte-range slice с `truncated`). MCP Resources провайдер удалён как непригодный для агента — массовые MCP-клиенты не auto-injectят resources, а `@`-mention продуктово не используется. Bundle не трогается.

- [ADR-0019](0019-intent-events-unified-history.md) — `intent_events` as unified Intent history (stage 2): новая append-only коллекция `intent_events` хранит все события интент-агрегата — `text_changed` (delta-формат из ADR-0002 сохранён), `link_added`, `link_removed`. Cut-over миграция `text_versions` (owner_kind=intent) → `intent_events` через одноразовый идемпотентный hosted service. `MongoIntentRepository` пишет только в `intent_events`; `MongoIntentLinkRepository` дополнительно пишет link-события. Link-события несут `peer_intent_id = to_id` — таймлайн фильтром `intent_id = X OR peer_intent_id = X` показывает событие на обоих концах ребра. Новый HTTP endpoint `GET /api/v1/intents/{id}/events` возвращает merged feed; `listIntentVersions` репоинтится на `intent_events` фильтром `kind=text_changed`. `Instruction.text_versions` не трогается.

- [ADR-0018](0018-intent-link-graph.md) — Intent link graph (stage 1): новая коллекция `intent_links` хранит направленные рёбра `(from_id, to_id, type)` с замкнутым множеством типов `relates` / `blocks` / `derived_from` (`duplicate_of` зарезервирован для stage 3). Граф ортогонален тексту: создание/удаление ребра не бампит `current_version`, не пишется в `text_versions`. `get_intent.links[]` отдаёт outgoing + incoming как единый список с inline-peer-preview; пагинированный read-доступ — `list_intent_links`. MCP-tools `link_intent` / `unlink_intent` / `list_intent_links`, HTTP-модуль (POST/DELETE/GET под `/api/v1/intents/{id}/links/...`), realtime-события `intent.link_added` / `intent.link_removed` через стандартный pipeline ADR-0008. Cascade-delete рёбер при удалении интента — by construction в `MongoIntentRepository`. Миграция `text_versions` → `intent_events` и UI-панель связей вынесены в stage 2.

- [ADR-0020](0020-intent-status-needs-help-and-fridge.md) — Inbox-pair (`needs_help` + `ready_for_review`) и `fridge` в статус-машине Intent: расщепляем «ход за оператором» на два явных статуса (агент закончил vs застрял), вводим пользовательский «холодильник», добавляем MCP-tool `mark_needs_help` симметрично `mark_ready_for_review`, в UI поднимаем кросс-контекстный Inbox-виджет в сайдбаре + псевдо-контекст «Холодильник» + quick-action «Завершить» на `ready_for_review`. Переходы плоские, валидация через `IntentStatusNames.IsKnown`; миграция БД не требуется.

- [ADR-0017](0017-removal-of-review-stage.md) — Removal of review stage: коллекции `intent_qa` / `intent_review`, MCP-инструменты `add_intent_qa` / `add_intent_review` / `mark_ready_for_work`, HTTP-эндпоинты `/intents/{id}/qa` и `/reviews`, realtime-события `intent.qa_added` / `intent.review_added` и instruction kind/bundle `fix` удалены целиком — функциональность дублируется анализом дампов переписки с агентом. Статус `ready_for_review` и MCP-tool `mark_ready_for_review` сохраняются как явный агентский сигнал «работа закончена». Переходы interview/work автоматические при чтении соответствующего bundle; follow-up на feedback тоже идёт через `mode=work`. Dream-окно — все intents c `current_version > 1`, без qa/review. Источник evidence для dream позже переведён на frontier-driven flow ([ADR-0022](0022-frontier-driven-dream-flow.md)).

- [ADR-0023](0023-mcp-tools-snake-case-naming.md) — MCP tool parameter snake_case легализован на editorconfig-уровне: каталог `apps/api/src/Throne.Api/Mcp/Tools/**.cs` — это API boundary, и `snake_case` параметры (intent_id, from_id, target_kind, …) — wire-format контракт MCP. CA1707 для этого каталога выключен через editorconfig-секцию; 7 pragma-suppressions удалены, общее число записей в `suppress-baseline.json` падает с 81 до 74. Pragma-уровень suppression создавал ложный сигнал «у нас technical debt», тогда как фактически имена — публичный контракт.

- [ADR-0024](0024-intent-repository-binding-and-cli-providers.md) — Intent ↔ Repository binding и git-provider shell-out: workspace-layout `{Throne:Workspace:Root}/intents/{intent_id}/{owner}__{repo}/` (плоский namespace, разделитель `__` исключает коллизии `foo/myrepo` vs `bar/myrepo` и даёт O(1) `ls` всех реп интента); один репозиторий в N интентах — независимые клоны (изоляция бранчей намеренная); порт `IGitProvider` + `ProcessRunner` shell-out в локально установленные `gh` / `glab` (своего OAuth-клиента не пишем); polling-only доставка PR-комментариев через `gh api` с conditional GET по ETag — webhook'и не нужны, Throne local-only; статус-машина `clone_status` = `pending` | `cloning` | `ready` | `failed` | `broken` (closed/merged PR не поллится, manual refresh доступен всегда); `POST .../sync` синхронный — возвращает свежие комменты в ответе и параллельно фанаутит `intent.pr_comment_added` через стандартный pipeline ADR-0008; 404 на upstream → `broken` без авто-предложений re-bind; MCP read-only by design (`get_intent.repositories[]`, write-операции — только UI; PR-комментарии агент читает CLI-провайдером `gh`/`glab`, отдельного MCP-tool под них нет — см. [ADR-0030](0030-mcp-surface-policy-cli-first.md)). § 9 (надстройка над polling-тиком): авто-привязка PR к ready-биндингу с пустым PR-слотом по совпадению head-ветки клона (ровно одно совпадение; ручной аналог — `POST …/repositories/{binding_id}/pull-request`) + авто-закрытие интента в `done`, когда все PR-несущие биндинги интента `merged` (системный хук, из любого нетерминального статуса, история с источником `pr_merge`).

- [ADR-0025](0025-domain-aggregate-style-rich-ddd.md) — Domain aggregate style: rich-DDD поверх satellite mutators. Нормативный target style для агрегатов `Throne.Domain` (`Intent`, `Instruction`, `InstructionPatch`, `Tag`, `DreamSession`, `IntentRepositoryBinding`) — `public static T Create/Restore` на самом агрегате, инварианты инлайн, state-переходы инстансными методами, `State { get; private set; }`. Запрещены отдельные `*Factory` / `*Guards` / `*Mutator` / `*Operation` / `*RestoreValidator` файлы под конкретный агрегат; разрешены domain services поверх нескольких агрегатов (`IntentTextSearch`) и чисто-вычислительные хелперы (`TextEditMatcher`, `FractionalIndex`). Strict-профиль maintainability-budget выводит `**/Throne.Domain/**.cs` из-под LOC/member/CC/fanOut/ctor лимитов через единый pathOverride; точечные Domain-override'ы (`constructorMaxDependencies:10` на Domain, `typeMaxPublicMembers:20` на `DreamSession`) поглощены общим. Единственный auto-гейт — NetArchTest «no `internal set` в Throne.Domain» — вводится отдельным PR после миграции 6 агрегатов; остальные запреты охраняются code review. Кастомные Roslyn analyzer-проекты намеренно не плодим.

- [ADR-0027](0027-runtime-model-native-host-process.md) — Runtime model: нативный хост-процесс для host-фич. Два режима запуска вместо одного контейнерного: (1) контейнерный дефолт (`docker-compose.yml --profile full`, api+web+mongo в контейнере, host-capabilities OFF, хаки удалены — из `api` убраны bind-mount'ы `~/.config/gh`/`~/.ssh`/`~/.claude` + `HostRoot`); (2) host-backend (`docker-compose.host.yml`: только web+mongo, API нативно на хосте `dotnet run` с `ASPNETCORE_URLS=0.0.0.0:5008`, наследует PATH → спавнит `code`/`claude`/`gh`/`git`/`tmux` напрямую, родной keychain/ssh-agent, capability-detect видит реальные тулы). Web→host-API без CORS: nginx-upstream параметризован env `THRONE_API_UPSTREAM` (envsubst-шаблон, `api:5008` дефолт / `host.docker.internal:5008` в host-режиме) + WS-upgrade в `/api/` для встроенного терминала. Переопределяет неявную Docker-предпосылку эпика; влияет на [ADR-0026](0026-embedded-terminal-capabilities-and-run-preflight.md) (terminal/capabilities больше не container-bound); [ADR-0024](0024-intent-repository-binding-and-cli-providers.md) (CLI-proxy) остаётся в силе. Tauri/desktop-упаковка, Windows tmux-паритет, embedded-Mongo — out of scope.

- [ADR-0026](0026-embedded-terminal-capabilities-and-run-preflight.md) — Embedded agent terminal + capability gating + tag default repositories + Run pre-flight (Slice 2): singleton `capabilities` (`repositories`/`terminal`/`vscode`, default OFF, explicit opt-in, read-time materialization), embedded tmux-сессия `throne-{intent_id}` (имя детерминированно по intent_id, источник правды — `tmux has-session`, никаких новых полей на `Intent`), отдельные REST-эндпоинты `POST /api/v1/intents/{intent_id}/terminal/run|restart`, bidirectional WebSocket `/api/v1/intents/{intent_id}/terminal/ws` с контрактом в собственном `specs/contracts/realtime/websocket/terminal.yaml` (выбор vs AsyncAPI 2.6 зафиксирован с pro/contra; trigger to revisit — 3-й bidirectional канал), `Tag.default_repositories[]` + `GET /tags/{id}` (новый `TagDetailDto`) + `PUT /tags/{id}/default-repositories` (whole-replace + `expected_version`). Run pre-flight stateless-идемпотентен: union `Tag.default_repositories` ∖ existing bindings → parallel partial clone (`--filter=blob:none`, лимит `Throne:Clone:MaxParallel`=4) → blocking-ожидание `clone_status=ready` → spawn `tmux new -ADs throne-{intent_id} -- claude "..."`; failed/broken блокируют spawn → `session_state=blocked` + `blocking_bindings`. Bundle-read из MCP не триггерит pre-flight. Доставка `session_state` — поле в ответе Run, без нового SSE-события (realtime-yaml без правок; trigger to revisit зафиксирован). Capability retrofit Slice 1: `repositories` стартует OFF без миграции и onboarding-toast'ов; existing binding'и скрываются. MCP write-surface для terminal/capabilities/tag-defaults не вводится — read-only by design. § 8 (пересматривает § 7): переход интента в `done` (авто-по-мерджу PR или ручной) убивает tmux-сессию через хук на `IntentStatusChanged`, идемпотентно и безусловно; `reject`/`fridge` сессию не трогают.

- [ADR-0022](0022-frontier-driven-dream-flow.md) — Frontier-driven dream flow: после прогона раннего insight-pipeline и постмортема локальный pipeline (static extractor + Qwen3-Coder через MLX + chat_uploads transfer) демонтирован целиком. Throne становится memory + patch-proposal сервисом: фронтир-агент сам читает диалоги локально через `Read`/`Glob` по путям из нового MCP-тула `get_dream_sources`, рефлексирует по прошлым applied-патчам, обсуждает находки с пользователем и предлагает `propose_instruction_patch` против `work` и `interview` user-инструкций. Append-only сущность `DreamSession` (`record_dream_session` / `list_dream_sessions`) хранит память о проходах: vendor, период, `processed_conversation_ids`, `summary`, `reflection`, `proposed_patch_ids` — чтобы следующий проход не пересматривал то же и видел эффективность прошлых правок. UI `/improvements`: кнопка «Скопировать промпт» + вкладка Dreams с историей сессий и таблицей `dream_sources`. **Заменяет** ранний серверный insight-pipeline, поток chat-history transfer и предыдущую DreamRun-модель. Удалены: InsightCard / AnalysisJob / ChatUpload / ChatConversation / ChatMessage домены и Mongo-коллекции, vendor parsers, llama.cpp adapter, CLI `apps/cli`, MCP-тулы `list_insight_cards` / `get_insight_card` / `dismiss_insight_card` / `read_chat_span`, bundle `transfer`, realtime-события `insight_card.*` / `analysis_job.*` / `chat_upload.*` / `chat_conversation.*`. Cross-device sync `processed_conversation_ids`, авто-триггер dream и авто-применение патчей — out of scope.

- [ADR-0028](0028-quality-harness-recalibration.md) — Quality harness recalibration (audit-driven): strict-профиль `backend-maintainability` калибруется по месяцу сессий. Cyclomatic (`CA1502`) и class coupling (`CA1506`) Roslyn-аналайзеры **выключены** — единый SoT для этих измерений — `.quality` budget (per-method CC ≤10 + file fan-out ≤15); убран двойной энфорс, ~11 per-file dodge-секций и пороги `CA1502/CA1506` в `CodeMetricsConfig.txt`. `constructorMaxDependencies` поднят 5→8 (P98 сервисных классов), `record`-типы исключены из метрики на уровне чекера (primary-ctor поля — данные, не DI). `methodLocToleranceFactor: 1.25` гасит boundary-friction round-number LOC-лимитов (`81 > 80` больше не валит). `Throne.Domain` выведен из size-бюджета через `exclude` вместо pathOverride `9999`; rich-DDD инвариант охраняет активный `DomainEncapsulationRulesTests` (NetArchTest). **Amends [ADR-0025](0025-domain-aggregate-style-rich-ddd.md)** (механизм Domain-послабления). - [ADR-0031](0031-repository-and-verification-artifacts.md) — Repository-знание и PR-верификация как два сфокусированных контракта (не общая модель): обобщённый `Artifact` со `scope`-дискриминатором отвергнут как генерик-CMS с null-полями. Вместо него две независимые сущности (rich-DDD [ADR-0025](0025-domain-aggregate-style-rich-ddd.md), Throne-owned Mongo). **`RepositoryArtifact`** — свободная titled markdown-страница знаний на `Repository` (`db_schema_map` — страница по соглашению `slug=db-schema-map` с erDiagram-рендером, не жёсткий enum); **версионируется с append-only историей развития** (`repository_artifact_versions`, [ADR-0002](0002-domain-model-and-text-versioning.md) optimistic concurrency); AI/human-курируемое, **приватно владельцу — в контекст агента не подаётся**; единственная MCP-точка — authoring `write_repository_document` / `get_repository_document` (обобщает именованный `write_repository_schema`, сессия `schema_map`). **`PullRequestArtifact`** — one-shot выход верификации **PR-конкретного binding'а** (`binding_id` + `pull_request_number`, **не intent-scoped**), retention latest per `(PR, type)` без истории; `type` — открытая метка (static_analysis/coverage/call_diagram/review_recommendation/…), `render` ∈ markdown|mermaid|svg|json; в основном статика + часть AI; **только UI, вне MCP/контекста агента**; producer/ingestion **намеренно открыт** — нейтральный durable write через порт `IPullRequestArtifactSink` за идемпотентным REST-ingest. **Правит Slice 3** (`e93593d0`): `db_schema_map` — первая страница `RepositoryArtifact` с историей, а не поле `Repository`; PR-верификация — отдельная сущность, не на `Repository`. Realtime — две семьи `repository.document_updated` / `pull_request.artifact_updated` ([ADR-0008](0008-realtime-contract-first-events.md)). UI — страницы знаний + таймлайн версий на странице репо; PR-панель в placement `review` (capability `repositories`) через реестр панелей детали интента. Перспектива (не в ADR): `CommitArtifact` — та же one-shot форма с якорем `commit sha`, вводится отдельным слайсом по потребителю, переиспользует форму `PullRequestArtifact`. Out of scope: producer-контракт PR-верификации, static-analysis/diagram движки, версии у PR-артефактов.

- [ADR-0030](0030-mcp-surface-policy-cli-first.md) — MCP surface policy (CLI-first): MCP-surface сознательно узкий — tool проходит только если это (1) **context-read** компактного контекста интента, которого агенту иначе не достать (текст/версии, link-граф, attachments, instruction-bundle, dream-sources, `get_intent.repositories[]`; отдельный list-handle — только при реальной context-window/пагинации, не «на всякий случай»), либо (2) **rare agent-authored write** — именно работа агента над интентом (правки текста ADR-0003, статус-переходы, link-граф, `propose_instruction_patch`, узкое исключение `write_repository_schema` для schema_map). Всё остальное — **CLI-first**: shell/git/git-provider/OS/repo-операции агент делает локальным CLI в workspace (`git`/`gh`/`glab`/файлы/terminal), не MCP-tool'ом. PR review-комментарии — `gh`/`glab` или UI-prompt-контекст, не durable local store и не MCP-tool (фиксирует анти-паттерн `list_intent_pr_comments`); bind/unbind/sync — UI (ADR-0024 § 8); terminal/capabilities/tag-defaults — read-only (ADR-0026). Критерий на code review: «может ли агент сделать это локальным CLI в workspace?» → да ⇒ tool не заводим. Кодифицирует принцип, к которому ADR-0003 / ADR-0024 § 8 / ADR-0026 приходили по отдельности.

- [ADR-0033](0033-review-thread-resolution-and-comment-anchors.md) — Якоря и резолюция review-комментариев (Slice B ревьюилки): `PullRequestCommentDto` обрастает nullable `line` / `side` (`ReviewCommentSide`, один wire-формат строкой) / `resolved` / `thread_id`; `resolved` всегда читается из ответа провайдера, локального статуса нет (инвариант [ADR-0024](0024-intent-repository-binding-and-cli-providers.md) сохранён). Порт `IGitProvider` +2 метода `ResolveReviewThreadAsync`→`ReviewThreadState` (gh `resolveReviewThread`/`unresolveReviewThread` graphql-мутация; glab `PUT discussions/:id?resolved=`) и `DeleteReviewCommentAsync` (gh `DELETE pulls/comments/{id}`; glab `DELETE discussions/:id/notes/:note_id` — нужны thread_id+comment_id). - [ADR-0032](0032-gitlab-provider.md) — GitLab как второй git-провайдер: достраивает provider-neutral контракт [ADR-0024](0024-intent-repository-binding-and-cli-providers.md) до паритета с GitHub, не вводя новый слой. `GitLabCliProvider : IGitProvider` поверх `glab` (read-операции через сырой `glab api -H/-i`, своего OAuth нет), регистрируется в `IGitProviderRegistry` рядом с GitHub. `RepoCoordinate` обобщается (provider-aware валидация): GitLab `Owner` = namespace-path (`group/subgroup`, вложенность до 20 уровней), `Repo` = leaf; каталог `{owner}__{repo}` не парсится обратно, поэтому `/`→`-` в имени, плоский `ls` (ADR-0024 § 1) сохранён; на binding добавляется числовой `project_id` (стабильность к rename). Repo-эндпоинты обобщаются на route `/api/v1/git-providers/{provider}/repositories/...` (GitHub-хардкод снимается, gate `contracts` ловит drift); capability `gitlab` (default OFF) + `repositories`; MR↔PR — переиспользуем абстракцию без переименования; MCP остаётся read-only ([ADR-0030](0030-mcp-surface-policy-cli-first.md)).
